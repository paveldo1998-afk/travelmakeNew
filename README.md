# TravelOrganizer PWA

TravelOrganizer — работающий веб-клиент органайзера путешествий: поездки, сборы, план по дням, локальные документы, задачи и финансы. Интерфейс реализован на HTML/CSS/JavaScript по утверждённому [визуальному образцу](docs/ui-reference/approved-travel-reference.png), с фотографиями направлений, кремовыми поверхностями и терракотовыми действиями.

Текущая работа ведётся в ветке `feature/pwa-reference-redesign`. Публикация GitHub Pages и `main` обновляются отдельно после приёмки. Публичный адрес проекта — [paveldo1998-afk.github.io/travelmakeNew](https://paveldo1998-afk.github.io/travelmakeNew/); до публикации этой ветки он может показывать предыдущую версию.

## Запуск

Проверенная среда разработки: Node.js 24.22.1. Для браузерных проверок используется установленный Google Chrome и Playwright.

```powershell
cd F:\travelmakeNew
npm ci
npm start
```

Откройте **http://127.0.0.1:4173/travelmakeNew/**. Сервер перенаправляет корневой URL на этот путь. Для другого порта: `npm start -- --port 4180`.

Обычный запуск показывает ваши локальные данные либо настоящее пустое состояние. Заполненный пример открывается кнопкой «Открыть деморежим» в профиле или по адресу **http://127.0.0.1:4173/travelmakeNew/?demo=1#/trips**. Демонстрационная база отделена от основной; выход из демо сохраняется при перезагрузке.

Приложение не требует сборщика и не загружает runtime-фреймворк. Шрифты, основные фотографии и иконки поставляются локально. `npm ci` устанавливает инструменты проверки. Не открывайте приложение через `file://`: ES-модули, установка и service worker проверяются на localhost или HTTPS. [Требования к установке PWA — MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

## Что работает

| Область | Фактическое поведение |
| --- | --- |
| Поездки | Создание и редактирование, открытые даты, обложка по желанию, архив, поиск и удаление с подтверждением |
| Сборы | Вещи, количество, категории, ответственный как локальная метка, заметка и ссылка; ровно три состояния; поиск, фильтры, обычный выбор состояния и дополнительное удержание/перенос |
| Шаблоны | Собственные именованные наборы, правка, копирование, удаление и подтверждённое применение; новые вещи независимы и начинаются с «Ещё нет» |
| План | Дни и временная последовательность, события без дня, редактирование и назначение/очистка даты с сохранением ID и связей |
| Документы | Метаданные отдельно от настоящего файла; загрузка PDF/PNG/JPEG/WebP до 10 МБ, локальный просмотр, закрепление, отдельное удаление копии и записи |
| Задачи | Создание, редактирование, выполнение и удаление; срок по желанию, этап поездки, время/зона и календарь подготовки по месяцам |
| Финансы | Плановый бюджет, категории, счета «С собой»/«В номере», расходы, переводы, история, отмена операции и точные десятичные суммы; ручной курс другой валюты с датой |
| Контакты и история | Локальный каталог, телефон/адрес/ссылка, копирование адреса и локальный журнал изменений |
| Настройки и данные | Светлая/тёмная/системная тема, экспорт с содержимым файлов, проверяемый импорт без молчаливой перезаписи, управление копиями и очистка выбранного режима |
| PWA | Manifest, иконки, hash-маршруты, ограниченный service worker, офлайн-оболочка после загрузки и обновление по явному действию |

**Серверные функции не подключены.** Google/Apple-вход, роли и приглашения, права файлов, настоящая переписка, серверная синхронизация, push-расписание, карта, автоматические курсы и общие взаиморасчёты не имитируются. Их экраны объясняют ограничение. В деморежиме сообщения и голосование изменяют только отдельные синтетические записи на устройстве. Сохранённое напоминание и разрешение уведомлений не обещают доставку при закрытом приложении.

Для будущего продукта требуется настоящая авторизация. Текущая работа с пользовательскими записями явно обозначена как **локальный режим разработки**.

## Сохранность данных

Основная IndexedDB — `travelorganizer.pwa.v2`, демобаза — `travelorganizer.pwa.v2.demo`. Записи и Blob-файлы сохраняются транзакционно. Интерфейс сообщает об успехе после завершения транзакции; отказ квоты или доступа оставляет форму открытой с введёнными значениями.

Старый ключ `localStorage["travelorganizer.multitool.v1"]` проверяется и однократно переносится в IndexedDB. Исходная строка остаётся в localStorage и в метаданных миграции. Сохраняются идентификаторы, даты, связи, текущие остатки и суммы; старая история не применяется повторно. Ошибка чтения не подменяет данные демопримером. Старый `cached: true` сохраняется как историческая отметка, а наличие файла подтверждается реальными байтами.

Экспортируйте резервную копию через «Профиль → Данные на устройстве». Экспорт содержит сохранённые локальные файлы. При совпадении ID с отличающимися данными импорт прекращается без перезаписи. Хранилище браузера не является зашифрованным сейфом; другие проекты того же GitHub Pages origin не изолированы одним путём сайта. Не используйте публичный репозиторий и тестовые снимки для настоящих чувствительных документов.

## Установка и офлайн

В поддерживающем Chrome/Edge используйте действие «Установить PWA» либо соответствующий пункт меню браузера. Если browser install prompt недоступен, приложение показывает инструкцию и продолжает работать во вкладке.

На iPhone откройте сайт в Safari: «Поделиться» → «На экран Домой» → «Добавить». Если показан переключатель «Открывать как веб-приложение», оставьте его включённым. Это отдельный системный сценарий, а не Chromium prompt. [Официальное руководство Apple](https://support.apple.com/guide/iphone/iphea86e5236/ios).

После первого успешного открытия дождитесь сообщения о готовности оболочки в настройках. Код, стили, локальные шрифты и базовые фотографии затем доступны без сети; личный документ открывается офлайн только при сохранённом Blob. Новая версия ожидает явного обновления: изменённую форму сначала нужно сохранить либо подтвердить выход без сохранения.

## Проверки и изображения

При работающем локальном сервере:

```powershell
npm test
npm run test:browser
node scripts/capture.mjs
node tests/installability.mjs
```

Браузерные сценарии используют отдельные контексты и синтетические данные. `npm run test:browser` требует установленный Chrome. Адрес можно переопределить через `TRAVELORGANIZER_TEST_URL`; для снимков используется `TRAVEL_PREVIEW_URL`. Последняя команда проверяет Chromium installability и разбор manifest в новом принадлежащем проекту профиле; она не выполняет установку в ОС.
