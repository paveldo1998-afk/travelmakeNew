# TravelOrganizer PWA — фактическая проверка

Дата: 30 октября 2026 года. Проверяется работающий PWA из текущей ветки. Исторические макеты Figma и спецификации не используются как доказательство исполнения веб-клиента.

## Среда и воспроизведение

Браузерный отчёт [results.json](browser-checks/results.json) фиксирует Google Chrome **137.0.7151.120**, запущенный headless через Playwright, localhost `http://127.0.0.1:4173/travelmakeNew/`, отдельные browser contexts и только синтетические данные. Это установленный на машине браузер; сам PWA нативно в ОС не устанавливался в этом тесте. Node.js в рабочей среде — 24.22.1.

```powershell
npm ci
npm start
```

В другом терминале:

```powershell
npm test
npm run test:browser
node scripts/capture.mjs
node tests/installability.mjs
```

Сервер должен продолжать работать во время браузерного набора. Для другого адреса сценарии читают `TRAVELORGANIZER_TEST_URL`, снимки — `TRAVEL_PREVIEW_URL`. Файлы и записи тестов синтетические; реальный профиль пользователя и все origin-хранилища не очищаются.

Поле `pwa.version` машинного отчёта фиксирует версию именно проверенного прогона. Браузерный сценарий подтверждает `offlineReady: true`, scope `/travelmakeNew/` и 32 записи в собственных публичных кешах.

## Проверки хранилища и денег

`npm test` завершён: **15 тестов, 15 pass, 0 fail**. Набор `tests/storage-domain.test.mjs` использует Node test runner с fake-indexeddb. Он проверяет точную арифметику/валютную точность, повторяемую миграцию, сохранение более точных исторических дробей, повреждение/отказ доступа, атомарный rollback записей и байтов при отказе, составные ключи файлов, удаление только файлов своей поездки, исправление производных денежных полей, конфликт ревизий, идемпотентный экспорт/импорт, отказ перезаписи существующих байтов, безопасную очистку и отклонение опасных импортируемых структур.

Проверка использует модель IndexedDB в Node для воспроизведения отказов и отдельный настоящий Chromium IndexedDB в браузерных сценариях. Это разные уровни проверки; fake-indexeddb не выдаётся за реальный мобильный браузер.

## Установка, кеш и ограничения проверки

Manifest содержит стабильный ID, standalone display, scope/start URL, обычные и maskable иконки. Worker зарегистрирован в пределах проекта; публичный кеш ограничен allowlist ресурсов и собственным prefix. User/API/Blob-данные не кешируются общим service worker. Требования secure context и жизненный цикл обновлений сверены с [MDN: установка](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable) и [MDN: service workers](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers).

Отдельная [диагностика Chromium](browser-checks/installability.json), воспроизводимая `node tests/installability.mjs`, завершена в новом принадлежащем проекту persistent-профиле: `installabilityErrors: []`, `manifestParseErrors: []`. Это обычный изолированный профиль, а не incognito и не реальный профиль пользователя. Созданный тестовый профиль удаляется после проверки. Положительная диагностика подтверждает условия установки, распознанные этим Chromium, но не нажатие системной кнопки установки и не запуск установленного приложения.

Проверены браузерный manifest, worker scope, offline-ready, фактический offline reload/cold tab, сохранность Blob и контролируемое обновление. **Не проверены реальная установка в ОС, нативное установленное окно, настоящий iPhone/Android, Safari/WebKit/Firefox, виртуальная клавиатура, TalkBack и VoiceOver.** Эмуляция standalone и CSS-текста 200% не заменяет эти устройства и системные режимы.

Инструкция iPhone дана по [Apple](https://support.apple.com/guide/iphone/iphea86e5236/ios): Safari → «Поделиться» → «На экран Домой», с «Открывать как веб-приложение» при наличии. Общий install prompt Chromium для iPhone не обещается.

Сервер авторизации, роли/приглашения, ACL файлов, синхронизация, настоящая переписка и голосования, push-планирование, карты, автоматические валютные курсы и общие взаиморасчёты отсутствуют. В интерфейсе это обозначено; соответствующие действия не объявляются успешно подключёнными.

Слияние в `main` и публикация GitHub Pages не входят в автоматическую проверку и требуют отдельной приёмки владельца. Рабочая ветка — `feature/pwa-reference-redesign`.
