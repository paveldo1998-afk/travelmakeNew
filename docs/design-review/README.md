# TravelOrganizer: первая редактируемая версия Figma

Это экспорты **Figma**, а не снимки браузера и не новый PWA. Код приложения в этой итерации ещё не изменён: владелец потребовал согласовать Figma до реализации.

- [Figma Design System](https://www.figma.com/design/W42BoaNlUbZcWUaoe9yYFa)
- [Галерея сравнения](index.html) — открыть локальный HTML в браузере.
- [Все восемь экранов на одном изображении](figma-eight-screens.png).
- Каждый отдельный PNG сохранён в исходном размере **390 × 844**.

Файлы `reference-interiors/` — производные для сравнения внутренней области; неизменённые оригиналы находятся в `../ui-reference`. Приближённые координаты исключения рамки и выреза записаны в `reference-interiors/manifest.json`. Экраны Figma не изменены при подготовке галереи.

## Фактическое состояние

Восемь основных экранов построены из редактируемых текстовых слоёв, векторов, экземпляров компонентов и отдельных фотографий. В источниках экранов нет слоя полного коллажа. Исходный коллаж помещён отдельно на странице системы.

Первая проверка выявила дефекты, перечисленные ниже. Вызов исправления не был исполнен: Figma вернула `Figma MCP tool call limit` для Starter. Во второй уже подключённой учётной записи проверка вернула отсутствие edit access к тому же файлу. Владелец сообщил о намерении предоставить права редактора; фактическое получение прав ещё не подтверждено инструментом. Интеграция и тариф не переустанавливались и не менялись.

| Экран | Что подтверждено просмотром | Что исправить перед согласованием |
| --- | --- | --- |
| Поездки | Две фотокарточки, даты, участники, архив, создание | Порядок по ближайшему выезду: Италия в апреле должна быть раньше Японии в октябре |
| Обзор | Фото 260 px, градиент, участники, дни без выдуманных часов, сетка 2 × 3 | Нижние закрепления продолжаются за экраном; проверить узкую навигацию |
| Сборы | Три состояния, 12/36, компактные категории | Видимое добавление; круглые индикаторы вместо неоднозначных пустых чекбоксов |
| План | Лента дат, временная ось, фото 58 × 82 | Наложение двух описаний и адресов, частично скрытые нижние действия |
| Документы | Категории, поиск, записи без файла отдельно обозначены | Аудитория и локальные байты должны стать двумя независимыми признаками; отступ кнопки |
| Задачи | Сроки, ответственные, задачи без даты, вход в календарь | Обрезанный фильтр, пустая галочка завершённой задачи, группировка, видимое добавление |
| Обсуждения | Демо-переписка, карточка места, реакции, голосование | Первое сообщение и поле ввода обрезаны; композер требует собственной области |
| Бюджет | План 2450, расходы 1620, остаток 830, счета отдельно | Поднять перевод/историю; уплотнить категории; уточнить подпись 66% |

Финансовая арифметика синтетического примера проверена: 620 + 540 + 320 + 80 + 40 + 20 = 1620; 2450 − 1620 = 830; 1620 / 2450 ≈ 66%. Остатки двух счетов 300 и 500 не объявляются бюджетом.

Дополнительные 40 экранов описаны в `../design-work/additional-screens.json`, сборка подготовлена в `06-additional-screens.js`. Они **ещё не созданы на холсте**. Наличие скрипта не подтверждает результат его исполнения.

## Продолжение с сохранением файла и ID

1. Проверить фактический edit access к существующему файлу, не создавать дубликат.
2. Продолжить с `design-system-state.json`. Для вызовов Figma сохранять `fileKey` и актуальную сессию инструмента.
3. Выполнить отдельными вызовами `03-screen-helpers.js` + `05a-component-corrections.js` на странице системы и `03-screen-helpers.js` + `05-main-corrections.js` на странице основных экранов. В каждый скрипт передаётся `const S = <ledger>`.
4. Для дополнительных экранов передать `const S = <ledger>; const SPEC = <additional-screens.json>;` + `03-screen-helpers.js` + `06-additional-screens.js`. Это отдельная страница, один вызов.
5. Проверить результат структурно и реальным рендером Figma; исправить измеренные дефекты. Обновить экспорты и этот статус. Отдельно спроектировать тёмные значения с учётом ограничения одного mode.
6. Получить визуальное согласование владельца, затем реализовывать PWA. После этого провести браузерную, офлайн и миграционную приёмку основного задания.

Синтаксис скриптов проверен через `AsyncFunction` без обращения к холсту. Визуальные исправления и дополнительные макеты от этого не становятся проверенными. Проверки браузера PWA, 320/360/412 px, 200% текста, клавиатуры, IndexedDB, service worker, офлайна, обновления и установки ещё не выполнялись.
